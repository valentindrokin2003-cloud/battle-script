# Модерация и порт `IntentClassifier` — дизайн

## Краткое описание

Реализует два оставшихся домена из [HLD](./2026-09-03-battle-script-hld-design.md), которые стоят между `PromptSubmission` и уже готовым `BattleEngine`: `ModerationModule` (обязательный гейт до LLM) и порт `IntentClassifier` (ADR-003 — LLM за интерфейсом, не прямая зависимость). Реального вызова LLM в этой итерации не будет: в этом окружении нет доступа к API-ключу провайдера. Вместо адаптера на реальном LLM — детерминированный `LocalHeuristicClassifier`, closed-form заглушка на ключевых словах, которая реализует тот же интерфейс и позволяет собрать и протестировать весь пайплайн `PromptSubmission -> IntentClassification` без сети и без секретов. Настоящий LLM-адаптер подключается позже как второй адаптер того же порта, без изменений в domain/HTTP-слоях.

## Цели

- Дать интерфейс `IntentClassifier` в domain-слое (порт из ADR-003), который принимает текст + контекст класса героя/босса и возвращает `IntentClassification`, уже проходящую через `ValidateIntentClassification`.
- Дать `ModerationModule`: интерфейс + Phase-0 реализацию на списках/паттернах (профанити, попытки ввода PII, пустой/слишком длинный текст) — блокирующий этап до классификации, как зафиксировано в HLD.
- Дать `LocalHeuristicClassifier` — рабочую, тестируемую, детерминированную заглушку адаптера: распознаёт ограниченный набор ключевых фраз/шаблонов (близких к примерам из бизнес-плана и спек) и возвращает fallback с `confidence: low_fallback_used`, если ничего не распознано. Не LLM, не обращается к сети.
- Реализовать retry/fallback-контракт из HLD на уровне оркестрации (не внутри конкретного адаптера): один retry при ошибке адаптера, затем `DefaultFallback(class)` с `confidence: low_fallback_used`.

## Не-цели

- Не подключать реальный LLM-провайдер (Gemini/Claude/др.) — нет доступа к API-ключу в этом окружении; порт проектируется под это, реализация откладывается.
- Не строить полноценный NLP/ML классификатор в `LocalHeuristicClassifier` — это заглушка для разработки и тестов пайплайна, не production-путь для реальных детских формулировок.
- Не решать, как контент модерации будет обновляться/расширяться со временем (списки слов, локализация) — фиксируется только структура и Phase-0 объём.

## Порт `IntentClassifier`

```go
type ClassificationContext struct {
    HeroClass HeroClass
    Boss      Boss           // раскрытые фазы, для контекста LLM/эвристики
    PromptText string        // текст ПОСЛЕ модерации
}

type IntentClassifier interface {
    Classify(ctx context.Context, input ClassificationContext) (IntentClassification, error)
}
```

Оркестрирующая функция (`ClassifyWithFallback` или аналог) в domain-слое:

```text
1. classifier.Classify(ctx, input)
2. если err != nil ИЛИ ValidateIntentClassification(result, input.Boss) != nil:
     один retry classifier.Classify(...)
     если снова ошибка/невалидно -> вернуть DefaultFallback(input.HeroClass)
     с Confidence = low_fallback_used
3. иначе вернуть результат с Confidence, который проставил сам classifier (обычно "high")
```

Это прямая реализация раздела «Обработка ошибок» HLD и не зависит от того, какой конкретно адаптер за портом — заглушка или настоящий LLM.

## `ModerationModule`

```go
type ModerationResult struct {
    Allowed bool
    Reason  string // человекочитаемая причина отклонения, пусто если Allowed
}

type Moderator interface {
    Check(text string) ModerationResult
}
```

Phase-0 реализация (`BasicModerator`) — правило-ориентированная, без внешних вызовов:

- Пустой или ссылку на 0 символов после trim — отклонить («напиши тактику словами»).
- Длина текста больше разумного лимита (например, 500 символов) — отклонить (защита от злоупотребления/DoS на последующий LLM-вызов).
- Список запрещённых слов/паттернов (профанити на русском и английском, минимальный стартовый набор) — отклонить с причиной без цитирования самого текста обратно (не повторять оскорбление в UI).
- Паттерны, похожие на попытку ввода личных данных (email-like, телефон-like regex) — отклонить, потому что дети не должны вводить контактные данные в игровое поле ввода.

Список слов — Phase-0 отправная точка, не финальный; открытый вопрос ниже.

## `LocalHeuristicClassifier`

Детерминированная заглушка `IntentClassifier`, реализованная как таблица «шаблон текста → `TacticProgram`» на класс героя, соответствующая ровно тем формулировкам, что уже использованы как канонические примеры в предыдущих спеках (пример мага с «ледяным шаром», пример танка с провокацией). Работает по простому сопоставлению ключевых слов (например, содержит «щит» и «фаза» → правило `boss_phase_is`), не по NLP. Если ни один шаблон не подошёл — возвращает `DefaultFallback(class)` с `Confidence: low_fallback_used` напрямую (имитируя случай, когда классификатор не смог разобрать текст), не ошибку — так тестируется и happy path, и fallback-путь оркестрации без необходимости искусственно ломать реальный LLM-вызов.

**Явно не выдаётся за LLM**: имя типа и комментарий в коде должны прямо говорить, что это заглушка для разработки, а не деградированный режим продакшена — иначе есть риск случайно отправить её в Фазу 0 пилота вместо настоящего адаптера.

## Обработка ошибок

Наследует HLD и уточняет:

- `Moderator.Check` вызывается до `IntentClassifier.Classify` всегда; при `Allowed: false` классификатор не вызывается вовсе — конвейер останавливается на модерации.
- Ошибка/невалидный ответ классификатора (включая от `LocalHeuristicClassifier`, хотя по конструкции она не должна падать) обрабатывается общей retry/fallback-оркестрацией, не кодом внутри конкретного адаптера — это гарантирует одинаковое поведение при будущей замене на реальный LLM-адаптер.

## Тестирование и валидация

- `BasicModerator`: таблица кейсов (пусто, слишком длинно, профанити, email-like, телефон-like, обычный валидный текст) → `Allowed`/причина.
- `LocalHeuristicClassifier`: для каждого класса героя — минимум один кейс «текст узнан → ожидаемый `TacticProgram`» и один кейс «текст не узнан → fallback с `low_fallback_used`»; каждый узнанный результат дополнительно прогоняется через `ValidateIntentClassification`, чтобы заглушка не могла тихо начать возвращать невалидные данные.
- Оркестрирующая retry/fallback-функция: тест с моком `IntentClassifier`, который падает N раз подряд — проверяет, что ровно один retry происходит и после него используется fallback, не бесконечный ретрай.
- Интеграционный тест полного пути: текст → `BasicModerator` (проходит) → `LocalHeuristicClassifier` → `ValidateIntentClassification` → `SelectAction` — замыкает цепочку от сырого текста ребёнка до конкретного игрового действия впервые в проекте.

## Открытые вопросы

- Список запрещённых слов/паттернов для `BasicModerator` — минимальный стартовый набор для разработки, не прошедший ревью модератора контента/юриста; перед реальным пилотом требует профессионального ревью (COPPA/GDPR-K контекст), это явно не архитектурная работа.
- `LocalHeuristicClassifier`'а набор распознаваемых шаблонов — минимальный, только для тестирования пайплайна; не предполагается расширять его до продакшен-уровня вместо интеграции настоящего LLM.
- Момент и способ интеграции реального LLM-адаптера (Gemini/др.) — блокируется наличием API-ключа/бюджета у вас; когда будет доступ, добавляется как второй адаптер `IntentClassifier` без изменений в этой спеке.
